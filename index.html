HOW DISTRIBUTED LEARNING WORKS

Many ways to learn together.
One rule: the data stays home.

Distributed learning trains a model across participants without pooling raw data in one place. Methods differ in what crosses the network. TRAVI runs on TL++, and is not locked to a single method.

METHOD A

Federated Learning

Each participant trains a copy of the model on local data. Only model updates go to a server, which averages them into a new global model, round after round.

Moves
Model updates (weights or gradients)
Fits
Neural networks, linear models
METHOD B

Federated tree ensembles

Random forests and gradient-boosted trees can be built across participants. Each site grows trees on its own data, or shares split statistics, and the results are combined into one ensemble.

Moves
Trees or split statistics
Fits
Tabular data, Random Forest, XGBoost
METHOD C TRAVI CORE

Traversal Learning (TL++)

The model visits participants in turn. Only cut-layer activations and gradients move, and virtual batches give the same gradient updates as centralized training on the same batch. Intermediate computation is protected by multi-party computation.

Moves
Cut-layer signals only
Fits
Deep neural networks
ONLY WITH TL++

Value alignment

Every sample is checked against a participant's own values, so only data that fits enters training. Similar participants group into cohorts that build a shared model.

ONLY WITH TL++

Transparent attribution

Each sample's effect on the model is traceable, so reward maps directly to contribution. Conventional federated learning shares only aggregated updates, which makes per-sample tracking infeasible.

Turn scores into shares

Pay out on Hedera

Each settlement period pays participants on the Hedera network, according to the cooperative's sharing rule and each participant's cumulative contribution. Only revenue from contribution is shared.
